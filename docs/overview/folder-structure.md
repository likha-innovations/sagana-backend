# Folder Structure Blueprint

The `sagana-backend` project adheres to a clean, modular folder hierarchy designed to separate cross-cutting concerns, external infrastructure, and business domains.

---

## 🗂️ High-Level Directory Tree

```
sagana-backend/
├── bruno/                      # Git-tracked API test requests (Bruno collection)
├── docs/                       # VitePress documentation hub (this site)
│   └── .vitepress/             # VitePress configuration & theme settings
├── logs/                       # Runtime file logs generated by LoggerService
├── prisma/                     # Database ORM definition and migrations
│   └── schema.prisma           # Database models and relations
├── scripts/                    # Maintenance & operations utility scripts
│   └── delete-machines.ts      # Transactional machine hard-delete maintenance script
├── src/                        # Core application TypeScript source code
│   ├── core/                   # Cross-cutting framework utilities
│   ├── infrastructure/         # DB connection & external service adapters
│   ├── modules/                # Feature-based business domain modules
│   ├── app.controller.ts       # Root system endpoints (/health)
│   ├── app.module.ts           # Root NestJS module wiring
│   └── main.ts                 # Application entrypoint and bootstrapping
├── test/                       # End-to-end (E2E) integration test suites
├── package.json                # Dependencies and npm scripts
├── prisma.config.ts            # Prisma 7 configuration file
└── tsconfig.json               # TypeScript compiler options
```

---

## 🔍 Detailed Breakdown of `src/`

### 1. `src/core/` — Cross-Cutting Concerns
Shared infrastructure utilities that do not belong to any specific business domain:

* **`config/env.validation.ts`**: Zod schema validating critical environment variables (`DATABASE_URL`, `CLERK_SECRET_KEY`, `PORT`) at server boot.
* **`decorators/`**:
  * `public.decorator.ts`: `@Public()` metadata decorator to whitelist endpoints from the global auth guard.
  * `current-user.decorator.ts`: `@CurrentUserId()` param decorator extracting `req.user.id`.
* **`exceptions/global-exception.filter.ts`**: Catches all unhandled exceptions, maps Prisma error codes (like unique constraint conflicts), and returns standardized JSON errors.
* **`guards/clerk-auth.guard.ts`**: Global JWT verification guard using `@clerk/backend`.
* **`interceptors/transform-response.interceptor.ts`**: Standardizes all successful responses into `{ success: true, data: T, timestamp }`.
* **`logger/logger.service.ts`**: Custom console and asynchronous file logging with `Asia/Manila` timezones.
* **`pipes/zod-validation.pipe.ts`**: Validates request payloads against Zod schemas.

---

### 2. `src/infrastructure/` — External Adapters
Handles direct interaction with database drivers, brokers, and persistence:

* **`database/prisma.service.ts`**: Initializes PostgreSQL connection pooling with `@prisma/adapter-pg` and manages `$connect` / `$disconnect` lifecycle hooks.
* **`database/database.module.ts`**: Exports `PrismaService` globally for dependency injection in domain modules.
* **`mqtt/mqtt.service.ts`**: Connects securely over TLS to HiveMQ Cloud, manages automatic reconnects, topic subscriptions (`sagana/ping`, `sagana/devices/+/telemetry`), and publishes outgoing commands.
* **`mqtt/mqtt.module.ts`**: Global module exporting `MqttService`.

---

### 3. `src/modules/` — Business Domains
Isolated feature packages containing domain logic:

```
src/modules/
├── barangays/
│   ├── barangays.controller.ts     # Public endpoint for active barangay listings
│   ├── barangays.service.ts        # Barangay querying via Prisma
│   └── barangays.module.ts         # Module definition
├── feedstocks/
│   ├── dto/
│   │   └── feedstock.dto.ts        # Zod schema for feedstock records
│   ├── feedstocks.controller.ts    # Public endpoint (/feedstocks)
│   ├── feedstocks.service.ts       # Feedstocks data retrieval
│   └── feedstocks.module.ts        # Module definition
├── machines/
│   ├── dto/
│   │   ├── register-machine.dto.ts # Machine registration schema (MAC, name, Wi-Fi)
│   │   └── update-machine.dto.ts   # Update schema (name, Wi-Fi SSID)
│   ├── machines.controller.ts      # CRUD & registration endpoints (/machines)
│   ├── machines.service.ts         # Scoped machine logic, MQTT downlink & events
│   ├── machines.module.ts          # Module definition
│   └── *.spec.ts                   # Unit tests
├── telemetry/
│   ├── dto/
│   │   └── publish-command.dto.ts  # Zod schema for actuator/device commands
│   ├── telemetry.controller.ts     # REST endpoints (/telemetry/devices/:id/command)
│   ├── telemetry.gateway.ts        # Socket.IO Gateway (/telemetry namespace)
│   ├── telemetry.service.ts        # MQTT listener, ingest & event broadcast
│   ├── telemetry.module.ts         # Module definition
│   └── *.spec.ts                   # Telemetry unit tests
├── users/
│   ├── dto/
│   │   └── update-profile.dto.ts   # Zod schema & DTO for profile updates
│   ├── users-operator.controller.ts # Handlers for /me (GET, PATCH)
│   ├── users-admin.controller.ts   # Admin operator management handlers
│   ├── users.service.ts            # User queries and updates via Prisma
│   ├── users.module.ts             # Module definition
│   └── *.spec.ts                   # Unit tests
```
